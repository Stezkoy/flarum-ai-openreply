# Расширение AI Open-Reply для Flarum

![Лицензия](https://img.shields.io/badge/license-MIT-blue.svg) [![Latest Stable Version](https://img.shields.io/packagist/v/stezkoy/flarum-ai-openreply.svg)](https://packagist.org/packages/stezkoy/flarum-ai-openreply) [![Total Downloads](https://img.shields.io/packagist/dt/stezkoy/flarum-ai-openreply.svg)](https://packagist.org/packages/stezkoy/flarum-ai-openreply)

Расширение для [Flarum](http://flarum.org).

Автоматически отвечает на новые обсуждения (или на каждое сообщение автора темы) с помощью AI-ассистента. Ответы генерируются [opencode](https://opencode.ai) — headless-инстансом [opencode-сервера v2](https://opencode.ai/v2/docs/) (`opencode serve`) — и публикуются от имени назначенного пользователя-ассистента.

Для каждого обсуждения создаётся своя постоянная сессия opencode, поэтому ассистент сохраняет полный контекст разговора. Ответ ассистента вставляется в тему как обычный текстовый пост.

> **Требуется opencode v2.** Начиная с версии 3.0.0 расширение работает **только** с сервером opencode **v2** (`opencode serve`, API под `/api/*`). Серверный API opencode v1 больше не поддерживается. См. настройку сервера ниже.

Форк `michaelbelgium/flarum-ai-autoreply`, переработанный для работы с серверным API opencode v2.

## Требования

- **Flarum >= 2.0** и **PHP 8.3**
- Запущенный инстанс [opencode-сервера v2](https://opencode.ai/v2/docs/), доступный с хоста, на котором работает Flarum

## Установка

Установите через composer:

```sh
composer require stezkoy/flarum-ai-openreply
```

Затем выполните миграции:

```sh
php flarum migrate
```

## Установка opencode v2 на Ubuntu

Установите CLI `opencode` **v2** на машину, где работает Flarum:

```sh
curl -fsSL https://opencode.ai/v2/install | bash
```

Скрипт устанавливает бинарник `opencode` и выводит дальнейшие шаги. Либо установите его глобально через npm, чтобы бинарник оказался в `PATH` (удобно для systemd-сервиса позже):

```sh
sudo npm install -g @opencode/cli
which opencode   # -> /usr/bin/opencode
```

> Если ранее был установлен пакет v1 (`opencode-ai`), сначала удалите его — v1 и v2 не устанавливаются рядом, а установщик v2 заменяет бинарник v1.

Настройте хотя бы одного AI-провайдера для opencode (это делается один раз на машину, а не на сессию):

```sh
opencode auth login
```

## Настройка opencode-сервера

> AI-провайдер(-ы) и API-ключи настраиваются внутри самого opencode. Это расширение общается с opencode-сервером только по HTTP.

### Безопасный вариант по умолчанию: только localhost (рекомендуется)

По умолчанию сервер слушает `127.0.0.1`, поэтому он доступен только с той же машины. Запустите его с basic-аутентификацией и фиксированным портом:

```sh
OPENCODE_SERVER_PASSWORD=your-strong-password opencode serve --hostname 127.0.0.1 --port 49374
```

opencode v2 по умолчанию слушает порт `49374` — укажите **URL opencode-сервера** в расширении как `http://localhost:49374`, и всё готово. Ничего не выставляется в сеть; трогать брандмауэр не нужно.

### Внешний доступ (не рекомендуется)

Делайте так только если opencode-сервер должен жить на другой машине, чем Flarum. Обязательно задавайте пароль:

```sh
OPENCODE_SERVER_PASSWORD=your-strong-password opencode serve \
  --hostname 0.0.0.0 --port 49374 \
  --cors https://forum.example.com
```

Примечания:

- С `--hostname 0.0.0.0` сервер слушает все интерфейсы — ограничьте доступ брандмауэром (`ufw allow from <ip-flarum> to any port 49374`) и по возможности спрячьте его за TLS (обратный прокси Nginx/Caddy).
- `--cors` нужен только для клиентов в браузере. Это расширение вызывает API из PHP, поэтому CORS для его работы не требуется.

### Параметры `opencode serve`

| Флаг             | Описание                                          | По умолчанию  |
|------------------|---------------------------------------------------|---------------|
| `--port`         | Порт для прослушивания                            | `49374`       |
| `--hostname`     | Хост для прослушивания                            | `127.0.0.1`   |
| `--cors`         | Дополнительные источники для браузера (можно повторять) | `[]`    |
| `--service`      | Регистрация в качестве фонового системного сервиса | `false`      |
| `--stdio`        | Общение через stdio вместо HTTP                   | `false`       |

Аутентификация управляется переменными окружения:

- `OPENCODE_SERVER_PASSWORD` — включает HTTP basic-аутентификацию (обязательно, если сервер доступен кому-то ещё).
- `OPENCODE_SERVER_USERNAME` — имя пользователя для basic-аутентификации, по умолчанию `opencode` (именно это имя отправляет расширение).

### Запуск как systemd-сервис

Создайте `/etc/systemd/system/opencode.service`:

```ini
[Unit]
Description=opencode headless server (AI Open-Reply)
After=network-online.target
Wants=network-online.target

[Service]
Type=simple
User=opencode
WorkingDirectory=/var/lib/opencode
Environment=OPENCODE_SERVER_PASSWORD=your-strong-password
ExecStart=/usr/bin/opencode serve --hostname 127.0.0.1 --port 49374
Restart=always
RestartSec=3

[Install]
WantedBy=multi-user.target
```

Поправьте `ExecStart`, если `opencode` находится в другом месте (`which opencode`), затем:

```sh
sudo useradd -r -s /usr/sbin/nologin --home-dir /var/lib/opencode opencode
sudo mkdir -p /var/lib/opencode && sudo chown opencode:opencode /var/lib/opencode
sudo systemctl daemon-reload
sudo systemctl enable --now opencode
sudo systemctl status opencode
```

> Учётная запись `User=opencode` хранит собственные учётные данные провайдера и данные сессий. Добавьте `Environment=OPENCODE_SERVER_USERNAME=...`, если вы изменили имя пользователя basic-аутентификации.

### Запуск через Docker Compose

Самый простой способ поднять opencode-сервер на отдельной машине — например, на VPS — это Docker. Официальные образы публикуются на GHCR как `ghcr.io/anomalyco/opencode`. **Явно указывайте версию** — тег `latest` сейчас указывает на релиз opencode **v1**, поэтому всегда берите тег `2.x` (например `:2.0.0`).

1. На VPS установите Docker Engine с плагином Compose, затем создайте каталог проекта:

```sh
sudo mkdir -p /opt/opencode && cd /opt/opencode
```

2. Создайте `compose.yaml`:

```yaml
services:
  opencode:
    image: ghcr.io/anomalyco/opencode:2.0.0
    container_name: opencode
    restart: unless-stopped
    ports:
      - "49374:49374"
    environment:
      OPENCODE_SERVER_PASSWORD: "${OPENCODE_SERVER_PASSWORD:?задайте его в .env}"
      OPENCODE_SERVER_USERNAME: "${OPENCODE_SERVER_USERNAME:-opencode}"
    volumes:
      - opencode-config:/root/.config/opencode
      - opencode-data:/root/.local/share/opencode
      - opencode-workspace:/workspace
    working_dir: /workspace
    command: ["serve", "--hostname", "0.0.0.0", "--port", "49374"]

volumes:
  opencode-config:
  opencode-data:
  opencode-workspace:
```

3. Рядом создайте `.env` с паролем для basic-аутентификации:

```sh
OPENCODE_SERVER_PASSWORD=your-strong-password
# OPENCODE_SERVER_USERNAME=opencode   # необязательно; по умолчанию совпадает с именем пользователя расширения
```

4. Запустите сервер, проверьте логи и войдите в своего AI-провайдера (интерактивно, один раз):

```sh
sudo docker compose up -d
sudo docker compose logs -f opencode   # убедитесь, что сервер поднялся (Ctrl+C для выхода)
sudo docker compose exec -it opencode opencode auth login
```

Что происходит:

- В контейнере выполняется `opencode serve --hostname 0.0.0.0 --port 49374` — сервер слушает все интерфейсы на порту `49374`, basic-аутентификация включена через `OPENCODE_SERVER_PASSWORD` (имя пользователя — `opencode`).
- Тома `opencode-config` и `opencode-data` хранят на VPS учётные данные провайдера (`auth.json`) и все сессии обсуждений. **Они переживают `docker compose down` и обновление образа; удаляет их только `docker compose down -v`** — не запускайте его, если хотите сохранить сессии.
- `opencode-workspace` монтируется как `/workspace` (`working_dir`) — это проект, который сервер отдаёт в API.

Затем укажите сервер в настройках расширения в админке:

- **URL opencode-сервера** — `http://<ip-vps>:49374` (замените `<ip-vps>` на адрес вашего VPS)
- **Имя пользователя opencode-сервера** — `opencode`
- **Пароль opencode-сервера** — значение `OPENCODE_SERVER_PASSWORD`

Безопасность:

- Открывайте порт только для хоста с Flarum: `sudo ufw allow from <ip-flarum> to any port 49374 proto tcp`. Basic-аутентификация сама по себе не защищает от перебора пароля, а через API можно тратить деньги на генерацию ответов.
- Если VPS доступен из интернета, лучше поставить перед ним TLS (обратный прокси Caddy/Nginx).
- `--cors` не нужен — расширение обращается к API из PHP, а не из браузера.

Обновление:

```sh
cd /opt/opencode && sudo docker compose pull && sudo docker compose up -d
```

Чтобы перейти на свежий релиз, поднимите тег образа в `compose.yaml` (например `:2.0.0` → `:2.0.1`) и выполните команду выше. Сессии и учётные данные переживают обновление, потому что лежат в томах.

## Рекомендации по серверу

opencode — это локальная среда исполнения LLM-агента: она загружает модель, держит в памяти весь разговор (и часто всё окно контекста) и может запускать долгие фоновые задачи. Headless-сервер, который использует это расширение, — не исключение, поэтому планируйте ресурсы заранее.

### Производительность и стабильность

- **Запускайте его рядом с Flarum на отдельной машине (или в контейнере)**, а не в том же процессе, что PHP. Генерация ответа может быть медленной (от десятков секунд до минут), поэтому изолируйте сервер от веб-стека и выделите ему собственные CPU/память и сеть.
- **Убедитесь, что расширение может связаться с сервером.** У расширения таймаут запроса 600 секунд (`OpencodeClient`), так что медленная генерация — не проблема, но таймаут соединения — 5 секунд: сервер должен быстро отвечать на уровне TCP. Держите их в одной LAN / низколатентной сети, чтобы избежать ложных сбоев.
- **Следите за памятью.** У каждого обсуждения своя постоянная сессия; длинные разговоры и большие окна контекста накапливаются в RAM. Ограничьте число активных обсуждений или периодически перезапускайте сервис (`Restart=always` выше), чтобы освободить память.
- **Используйте быстрый канал до провайдера LLM и стабильного провайдера** — задержка генерации и лимиты провайдера определяют время ответа.
- **Включите токен-доступ / basic-аутентификацию**, чтобы не оставлять сервер открытым (см. раздел про аутентификацию выше).

### Минимальное / рекомендуемое железо

Это ориентировочные значения для конфигурации только на CPU, обслуживающей небольшой или средний форум. Берите выделенную VM или контейнер, а не разделяйте маленький VPS с тяжёлыми приложениями.

| Размер модели (примерно)          | RAM          | vCPU | Примечания                                |
|-----------------------------------|--------------|------|-------------------------------------------|
| Малая (облачные / хостинг-API)    | 2–4 ГБ       | 1–2  | Модель работает у провайдера, нагрузка локально небольшая |
| Локальная квантованная 7–8B       | 16 ГБ        | 4    | Удобно для работы с несколькими сессиями |
| Крупная 70B+ / много одновременных| 64 ГБ+       | 8+   | Тяжело; лучше использовать хостинг-API   |

Если вы используете хостинг-API (рекомендуется для большинства форумов), самому opencode нужно скромное железо — первая строка таблицы. Более крупные конфигурации оставьте для локальных моделей.



На странице настроек расширения в админке:

- **URL opencode-сервера** — адрес вашего headless-сервера opencode (по умолчанию `http://localhost:49374`, совпадает с портом v2-сервера по умолчанию).
- **Логин opencode-сервера** — имя пользователя для basic-аутентификации (по умолчанию `opencode`). Используется только если задан пароль.
- **Пароль opencode-сервера** — значение `OPENCODE_SERVER_PASSWORD`, если включена basic-аутентификация.
- **Агент (поведение)** — пресет, задающий стиль ответа: стандартный `build` (отвечает сразу) или `plan` (сначала обдумывает), либо по умолчанию. Если сохранённое имя неизвестно, серверная проверка откатывается к агенту по умолчанию (с предупреждением в логе), так что опечатка не сломает ответ.
- **Системный промпт (персона)** — необязательный свободный текст с инструкциями о поведении ассистента, например «называй себя Пупсик и отвечай по-русски». Хранится в сессии opencode каждого обсуждения (инструкции сессии, opencode 2.x) и попадает в контекст модели — персона не видна в сообщениях и может отличаться для каждого обсуждения.
- **Модель** — модель для ответов в формате `provider/model` (например `opencode/big-pickle`). Впишите её вручную либо нажмите **Получить бесплатные модели**, чтобы загрузить актуальные бесплатные модели с вашего opencode-сервера, и кликните нужную, чтобы она подставилась в поле. Пусто — использовать модель сервера по умолчанию. Модель независима от агента: агент задаёт *как* себя вести, модель — *какой ИИ* отвечает.
- **Пользователь-ассистент** — ID пользователя, от имени которого публикуются ответы AI (обязательно).
- **Бейдж пользователя-ассистента** — тумблер плюс текст в бейдже под постами ассистента. Выключен или пустой — бейдж не отображается.
- **Отвечать при создании обсуждения** — если включено, AI отвечает только при создании обсуждения. Если выключено, обсуждение превращается в чат между автором и ассистентом.
- **Теги** — ограничить работу ассистента конкретными тегами.
- **Действия** — три кнопки: **Проверить подключение** (health сервера + текущая модель), **Количество сессий** (всего сессий на сервере и сколько из них принадлежит расширению) и **Закрыть все сессии** (закрывает сессии расширения ограниченными партиями — если что-то осталось, нажмите ещё раз; остальные сессии сервера не затрагиваются).
- **Лимиты ресурсов** — `max_active_sessions`, `max_messages_per_session`, `session_ttl_days`. 0 — без ограничения.
- **Повторные попытки (ретраи)** — `retry_attempts` (общее число попыток, по умолчанию 1, максимум 10) и `retry_delay_seconds` (задержка перед каждой попыткой, по умолчанию 1, максимум 120) для запросов к opencode-серверу.

Агент и модель применяются при создании сессии, поэтому новые обсуждения подхватывают последние настройки. Персону ассистента можно задать прямо в настройках расширения выше (она попадает в инструкции сессии обсуждения); альтернативно персону можно «зашить» прямо в агента на сервере, например в `opencode.json`:

```json
{
  "agents": {
    "build": {
      "system": "You are a helpful assistant on a Flarum forum. Answer in the language of the user's post."
    }
  }
}
```

Также выдайте нужным группам пользователей разрешение «Использовать AI-ассистента».

## Возможности

- Автоответ на новые обсуждения с помощью AI
- Режим чата: обсуждение становится личным чатом между автором и ассистентом
- Постоянный контекст для каждого обсуждения (одна сессия opencode на обсуждение)
- Ответы публикуются как обычные текстовые посты от имени назначенного пользователя-ассистента
- Ограничение работы ассистента выбранными тегами
- Контроль прав на то, кто может запускать автоответ
- Ответы проходят полный цикл событий Flarum: счётчики обсуждения, указатели последнего поста и уведомления подписчиков остаются корректными
- Динамический список бесплатных моделей, загружаемый с opencode-сервера (без захардкоженных пресетов)
- Настраиваемые ретраи (`retry_attempts`, `retry_delay_seconds`) и лимиты ресурсов
